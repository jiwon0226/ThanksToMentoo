6가지 기술적 의사결정

① N+1 해결 (Bulk Fetch + Memory Mapping)

챕터별 진행 내역 도회 → Map O(1) 루프 조회로 전환. DB 쿼리 ~100번 → 2번.

② 복합키 설계 (내부 static class)

user_id + chapter_id 복합키. 소규모 프로젝트에서 가시성 우선 판단으로 내부 static class 방식 선택.

③ 순차 잠금 해제 알고리즘

파생 데이터 저장 대신 매 요청마다 실시간 계산. prevCompleted 플래그 기반 구현.

④ 업적 시스템 (Redis + 상수 클래스)

빈번한 카운터는 Redis, 영구 기록은 DB. AchievementIdCode 상수 클래스로 하드코딩 제거.

⑤ usePolling 커스텀 훅 (장 마감 자동 중단)

평일 09:00~15:30 체크 함수 작성. 컴포넌트별 폴링 주기 분리(1초·7초·6분).

⑥ Custom Event 패턴 (헤더 상태 동기화)

헤더 정보만을 위한 전역 상태 도입은 과하다 판단. window.dispatchEvent 기반 느슨한 결합.
